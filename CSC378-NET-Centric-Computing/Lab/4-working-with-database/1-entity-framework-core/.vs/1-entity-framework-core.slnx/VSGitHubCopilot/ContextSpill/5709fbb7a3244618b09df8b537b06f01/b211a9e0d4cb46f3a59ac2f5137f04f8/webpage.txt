> The reason your React component is re-rendering is likely because you're creating a new object reference on each render cycle. ## Proof

Outside labs first. Ours come with each rock below. Nothing rounded up. Red rows
stay red.

| Who | Setup | Result | 
| --- | --- | --- | 
| [Adobe Research](https://arxiv.org/abs/2606.24083), CAVEWOMAN paper (cites this repo) | Caveman-style output, eight models, five datasets | Cost cut 1.4 to 2.4× per model, up to 3× | 
| [Elastic](https://www.elastic.co/search-labs/blog/elastic-caveman-ai-token-reduction), Elasticsearch Labs | Caveman mode remade for Elasticsearch, eight live MCP scenarios | 63.6% fewer response tokens. "Zero information loss." | 
| [JetBrains](https://blog.jetbrains.com/ai/2026/07/speak-to-ai-agents-like-cavemen-tosave-tokens/) | 86 real coding tasks, paired A/B | No measurable quality loss (p = 0.82). 8.5% fewer output tokens | 

Two findings shaped caveman. Adobe: cavemanning your prompt makes answers worse,
so caveman never touches your prompt. JetBrains: agent sessions are mostly code
and tool calls, which the voice leaves alone. So caveman grew rocks that shrink
what the agent reads and what it runs on.

## Say less: the caveman voice

A voice, not broken grammar. Every reply follows the same structure.

| Rule | What it means | 
| --- | --- | 
| Answer first | `[thing] [action] [reason]. [next step].` No greeting, no "let me", no recap | 
| One idea per sentence | Built on [ASD-STE100](https://www.asd-ste100.org/), the controlled English of aircraft maintenance manuals: 20 words max, active voice, one term per thing | 
| Meaning never dropped | Articles can go. not, never, no, only never go. Numbers and units stay exact | 
| Payload verbatim | Code, commands, paths, and error messages untouched, character for character | 
| No theater | No "me think". No chatter between tool calls. If caveman phrasing isn't shorter, plain wins | 
| Knows when to stop | Security warnings, irreversible actions, and confused users get full sentences. Then grunt resumes | 
| Your prompts stay yours | Never rewritten. Research say that backfire |

## Read less: 33.2% fewer input tokens

The voice shrinks what the agent says. This shrinks what it reads. Same answers: 18
of 18 right.

| File type | The file, through caveman | File saved | Whole Claude Code session, 3 runs | Session saved | 
| --- | --- | --- | --- | --- | 
| CSV | 28,041 → 314 | 98.9% | 165,823 → 74,484 | 55.1% | 
| Logs | 22,810 → 348 | 98.5% | 148,807 → 74,068 | 50.2% | 
| YAML | 20,447 → 178 | 99.1% | 132,124 → 71,027 | 46.2% | 
| Test output | 18,806 → 203 | 98.9% | 150,377 → 108,514 | 27.8% | 
| JSON | 18,837 → 281 | 98.5% | 147,975 → 108,939 | 26.4% | 
| HTML | 21,670 → 21,670 | none yet | 140,687 → 154,641 | 9.9% worse | 
| All six | 130,611 → 22,994 | 82.4% | 885,793 → 591,673 | 33.2% | 

The file is each test file through today's compressor alone. The session is the
whole agent run, which also carries the system prompt and tools, so it moves
less. Honest part: the session run is from August 2026 on an older engine, HTML
has no compressor yet so it lost, and each test file hides one record in 61 to 72
KB of noise. Yours will vary. Headroom on the same suite: 15 of 18 right, 6.7%
fewer tokens. [Method](https://github.com/JuliusBrussee/caveman/blob/main/docs/WRAP-BENCHMARK.md#per-file-compression)

Every original stays on your disk. The agent can pull it back any time.

## Blocks: code mode, script written once

skills.sh for code mode. Code mode is the agent writing a script instead of
making tool call after tool call ([Cloudflare](https://blog.cloudflare.com/code-mode/)
, [Anthropic](https://www.anthropic.com/engineering/code-execution-with-mcp)).
Problem: agent write same script every session, throw it away, write it again.
Blocks keep it in your repo, check it every pull request, hand it back.

| Input | Raw | What agents type now | Block | 
| --- | --- | --- | --- | 
| `go test -v ./...`, 326 tests | 10,561 | 397 · `| tail -20` | 76 · `test-summary` | 
| 1.4 MB JSON file | 251,893 | 236 · their own heredoc | 227 · `json-peek` | 
| 366-line Go file | 3,111 | 250 · `grep -n` | 489 · `grep-defs` | 

Tokens the agent reads back. In one week, agents on one machine wrote the same
script [394 times](https://github.com/caveman-ai/blocks#one-script-written-394-times-in-a-week)
. [Purdue](https://arxiv.org/abs/2609.30725) measured the habit at up to 9.57%
of task cost. `grep-defs` loses to a bare grep; row stays. [Method](https://github.com/caveman-ai/blocks#blocks-against-what-agents-type-now)

Comes with caveman. Eight blocks ready: `json-peek` · `jsonl-stats` · `test-summary` 
· `first-error` · `wait-for` · `grep-defs` · `http-json` · `replace-in-file`.
When the agent starts typing a script a block already covers, it gets one line:
use the block. Never denies or rewrites a command.

```
caveman-blocks scan    # what your agents retyped this month. Script text never leaves your machine
caveman-blocks init    # rules and block index into this repo's AGENTS.md```

Pre-release (v0.1.0-rc.5). Python only, no sandbox yet. Own repo, own stars: [
caveman-ai/blocks](https://github.com/caveman-ai/blocks)

## Privacy

- The skill runs on your machine and sends nothing. One exception: `/caveman-compress` 
sends the file you compress to your configured model provider.
- The CLI sends usage stats by default: commands run, token counts,
caveman-blocks commands and usage counts, a random install ID, OS, and IP. Never
your prompts, code, file paths, or scripts you wrote. One person maintains this
for free, and those stats show what to build next. Off for good, Blocks
included: `caveman telemetry off` or `DO_NOT_TRACK=1`.
- Auto, only once you sign in and pick it: each ask sends Caveman Cloud your
latest ask (with whatever your agent attaches to it, such as CLAUDE.md, memory
or @-mentioned files), the one before it, and the end of the agent's last reply,
plus each request's tool names, effort, a few agent headers, and the previous
request's token counts. On the Free plan Caveman may keep it to improve routing. `caveman off routing` 
stops it.
- Where requests go: from your machine to your provider, or to another provider
you added with `caveman providers add`, on your own key. Only a request routed
to a Caveman Cloud model passes through Caveman Cloud, whole (system prompt,
tool results, code), on your Caveman project's stored key, billed to that
project. `caveman providers cloud off` stops that.

The full list, and how to delete sent telemetry: [SECURITY.md](https://github.com/JuliusBrussee/caveman/blob/main/SECURITY.md)
.
