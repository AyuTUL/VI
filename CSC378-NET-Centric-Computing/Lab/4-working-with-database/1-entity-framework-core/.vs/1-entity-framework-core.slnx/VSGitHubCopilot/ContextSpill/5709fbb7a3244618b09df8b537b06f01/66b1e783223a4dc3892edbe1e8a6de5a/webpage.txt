## Numbers

[![Share of the no-skill baseline. Lines of code: Ponytail v4.13 52%, Ponytail 5 47%. Output tokens: 57% and 55%. Cost: 84% and 74%. Time: 62% and 59%.](/DietrichGebert/ponytail/raw/main/assets/v5/chart.png)
](https://github.com/DietrichGebert/ponytail/blob/main/assets/v5/chart.png) 

[![Half the code, and yet better: 98% of risky logic ships with a test (no skill 68%); the agent's own tests catch 66% of injected bugs (no skill 46%).](/DietrichGebert/ponytail/raw/main/assets/v5/tests.png)
](https://github.com/DietrichGebert/ponytail/blob/main/assets/v5/tests.png) 

Two things the chart does not show: in a blind comparison, Ponytail 5's replies
beat the previous Ponytail's 110 to 67. And on the six security tasks (SQL
injection, path traversal, forged tokens, rate limiting, malformed CSV rows,
caching) it passed all 30 runs: less code, no less safe. Method, per-task tables
and limits: [benchmarks/results/2026-10-07-agentic.md](https://github.com/DietrichGebert/ponytail/blob/main/benchmarks/results/2026-10-07-agentic.md)
.

The rule was never "fewest tokens." It is: write only what the task needs, and
never cut validation, error handling, security, or accessibility. The code ends
up small because it is necessary, not golfed. Lower cost and latency are a side
effect.

## Before / after

[![Add a date picker to the frontend. No skill: 335 lines, a calendar and a date picker built by hand. Ponytail 5: one 10-line file that reuses the repo's Input with type date, so the browser brings the calendar.](/DietrichGebert/ponytail/raw/main/assets/v5/beforeafter.png)
](https://github.com/DietrichGebert/ponytail/blob/main/assets/v5/beforeafter.png) 

You ask for a date picker. Without Ponytail, the agent installs a date picker
library or builds a whole calendar by hand: 335 lines. Ponytail 5 first looks at
what is already there: the repo has an `Input` component, and every browser has
a date picker. It puts the two together. 10 lines.

More survivors in [examples/](https://github.com/DietrichGebert/ponytail/blob/main/examples)

## The review, rebuilt

[![The review, rebuilt. A real /ponytail-review finding from the benchmark: the change renamed a field, and an untouched file, src/routes/feed.js, now crashes. Must fix: the Atom feed now crashes on every request, with what this is, the problem, the fix, and what happens if we skip it. 100% of planted problems found, no skill 87%. 100% of problems outside the diff found, no skill 78%.](/DietrichGebert/ponytail/raw/main/assets/v5/review.png)
](https://github.com/DietrichGebert/ponytail/blob/main/assets/v5/review.png) 

`/ponytail-review` used to look only for code to cut. Now it reviews like the
senior dev who gets paged when it breaks: it reads the code your change touches,
not just the diff, and checks bugs, security, real load, missing tests, speed,
and what to cut. Each finding says what the code does, what goes wrong, how to
fix it, and what happens if you don't.

## The audit, rebuilt

[![Your whole repo, ranked. Fix this first. A real /ponytail-audit from the benchmark on a warehouse stock repo: 1 must fix, office batches with 1,200 fail completely; 2 must fix, the import silently skips bad rows; 3 must fix, a mistyped SKU in an office batch is silently ignored; 4 should fix, the risky code paths have no tests; 5 nice to have, the API crashes on a body that isn't an object. Verdict: fix 1 first.](/DietrichGebert/ponytail/raw/main/assets/v5/audit.png)
](https://github.com/DietrichGebert/ponytail/blob/main/assets/v5/audit.png) 

`/ponytail-audit` runs the same checks on the whole repo. It maps the code
first: entry points, how data moves, what load the project expects. Then it
ranks what it finds and tells you what to fix first. The old audit only listed
what to delete.

## New in 5.3: the band

[![The ponytail band in Claude Code, above the prompt. Detail mode: cost $23.80, last turn $1.14, average $0.72 per turn; 56.7M tokens, 168k output, 33 turns; agent time 52m 14s; reuse 71%, 5 used, 2 new; tests passed after the last change. Compact mode shows the same in one line.](/DietrichGebert/ponytail/raw/main/assets/band/band.png)
](https://github.com/DietrichGebert/ponytail/blob/main/assets/band/band.png) 

In Claude Code, ponytail now shows a band above the prompt: what the current
task costs, how many tokens and how much agent time it used, how often it reused
existing code instead of writing new code, and whether the tests passed after
the last change. Its buttons switch the level, run `/ponytail-review` or `/ponytail-audit`
, copy the task as Markdown, and fold the band into one line. Don't want it? `/ponytail band` 
hides it, the same command brings it back. Needs Claude Code 2.1.290 or later,
in the terminal or the desktop app. It does not show in the VS Code chat panel,
cloud sessions or `claude -p`.

[![The ponytail board, a local page: 61 sessions, 20h 13m agent time, $285.30 and 492.5M tokens in the last 30 days; agent time per project over time; the latest sessions with their tests; active days and streak.](/DietrichGebert/ponytail/raw/main/assets/band/board.png)
](https://github.com/DietrichGebert/ponytail/blob/main/assets/band/board.png) 

Board opens a local page with every task across your projects: cost, agent time
and tokens over time, every session with its tests, and the days you worked. By
default, everything stays on your machine, in `~/.config/ponytail/band/`. `/ponytail band import` 
adds your past Claude Code sessions to it, with their cost, agent time and
tokens.

## How it works

[![Before writing code, stop at the first rung that holds: 1 does this need to exist, 2 already in this codebase, 3 does the standard library do it, 4 a native platform feature, 5 an installed dependency, 6 can it be one line, 7 only then the minimum that works, plus one small test if it has logic.](/DietrichGebert/ponytail/raw/main/assets/v5/ladder.png)
](https://github.com/DietrichGebert/ponytail/blob/main/assets/v5/ladder.png) 

The ladder runs after it understands the problem, not instead of it: it reads
the code the change touches and traces the real flow before picking a rung. Lazy
about the solution, never about reading.

Lazy, not negligent: trust-boundary validation, data-loss handling, security,
and accessibility are never on the chopping block.

Logic with a branch, a loop, a parser, money or security leaves one small test
behind. Every reply ends with what was skipped or not checked and any risk you
should know.

## The prompt

Ponytail is one prompt: [`skills/ponytail/SKILL.md`](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md)
. The compact version, for agents that read a rules file, is [`AGENTS.md`](https://github.com/DietrichGebert/ponytail/blob/main/AGENTS.md)
. Everything else in this repo loads that prompt into different agents.

## Install

Claude Code, as two separate prompts:

```
/plugin marketplace add DietrichGebert/ponytail
```

```
/plugin install ponytail@ponytail
```

Codex:

```
codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail```

Then open `/hooks` in Codex, trust its two lifecycle hooks, and start a new
thread.

Any other agent: copy [`AGENTS.md`](https://github.com/DietrichGebert/ponytail/blob/main/AGENTS.md) 
into your project, or ask your agent to install [`skills/ponytail/SKILL.md`](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md) 
as a skill. Step by step for Copilot, Cursor, OpenCode, Gemini and the rest: [
INSTALL.md](https://github.com/DietrichGebert/ponytail/blob/main/INSTALL.md).

That was it. He'd be proud. He won't say it.

Active every session, with a handful of commands (see Commands). `/ponytail ultra` 
exists for when the codebase has wronged you personally. Startup and mode-change
text shows the current mode.

Only install ponytail from `DietrichGebert/ponytail` on GitHub or `@dietrichgebert/ponytail` 
on npm. It never ships `.exe` or `.dll` files; a copy that does is not mine.

## Commands

| Command | What it does | 
| --- | --- | 
| `/ponytail [lite | full | ultra | off]` | Set the intensity, or turn it off. No argument switches ponytail on at the default level if it is off, and otherwise reports the current level. | 
| `/ponytail band [on | off]` | Claude Code only: hide or show the band above the prompt. No argument switches it. The level stays. | 
| `/ponytail band import` | Claude Code only: add your past Claude Code sessions to the board, with their cost, agent time and tokens. | 
| `/ponytail-review` | Review the current diff like the senior dev who gets paged when it breaks: bugs, security, real load, risky code without a test, slow paths, and what to cut. Each finding says what the code does, what goes wrong, how to fix it, and what happens if you don't. Name a target in plain words to narrow or widen it: `uncommitted`, `staged`, `branch`, or a PR link. | 
| `/ponytail-audit` | The same check for the whole repo, most important first. | 
| `/ponytail-debt` | Harvest the `shortcut:` comments you've deferred into a ledger, so "later" doesn't become "never". | 
| `/ponytail-gain` | Show the measured impact scoreboard (less code, less cost, more speed) from the benchmark. | 
| `/ponytail-help` | Quick reference for the commands above. | 

Commands need a skill-capable host (Claude Code, Codex, Devin CLI, OpenCode,
Gemini, Antigravity CLI, pi, Hermes Agent, Qoder, Grok Build). In Codex CLI and
the IDE extension they're skills under the plugin's namespace; invoke with `$ponytail:ponytail-review`
. Cursor with the [hooks](https://github.com/DietrichGebert/ponytail/blob/main/INSTALL.md#cursor) 
gets `/ponytail` level switching only, typed as a plain message. The
instruction-only adapters (Cursor's rule file, Windsurf, Cline, Copilot, Kiro,
Antigravity's `AGENTS.md` fallback) load the always-on ruleset without the
commands.

## FAQ

Does it need a config file? No. An optional `~/.config/ponytail/config.json` or `PONYTAIL_DEFAULT_MODE` 
env var can set the default level, but nothing is required.

Why does it write `shortcut:` comments? They mark a deliberate shortcut and when
to revisit it, and `/ponytail-debt` collects them into a ledger. Want another
word, or none? Say so in your project's `CLAUDE.md` or `AGENTS.md`, then run `/ponytail-debt <your word>`
.

What if I really need the 120-line cache class? You don't. Insist anyway and
he'll build it. Slowly. Correctly. While looking at you.

Does it scale? The code you never wrote scales infinitely. Zero bugs, zero CVEs, 100%
uptime since forever.

Why "ponytail"? You know exactly why.
